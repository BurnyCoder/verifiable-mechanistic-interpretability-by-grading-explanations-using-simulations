# Second independent audit — results, methods and claims (2026-11-22)

*Reviewer stance: an adversarial NeurIPS-style review, made without reading the earlier reviews in this folder. Scope:
every file in the repository, the agents' build scripts and transcripts (`D:/AI/vmi-sim/runs`, published on
[Hugging Face](https://huggingface.co/BurnyCoder/grading-explanations-by-simulation)), the target repository on
Hugging Face, and every external citation. No new agent run and no API spend; all recomputation ran on the local GPU.
Changes are logged as preregistration deviation 9.*

## 1. How the audit was done

1. **Code against its definitions.** Read and checked the grader (`grader/metrics.py`), the statistics
   (`analysis/stats.py`), the hypothesis evaluation (`analysis/hypotheses.py`), the prediction and replication tables
   (`analysis/predictions.py`, `analysis/tables.py`), the frequency analysis (`analysis/frequencies.py`), the
   explanation ladder (`explainer/ladder.py`), the no-agent controls (`nonagent.py`), grokviz's `restricted_loss` and
   `key_frequencies`, the sandbox launch (`scripts/run_one.sh`, `simulator/sandbox.py`) and the build-script audit
   (`simulator/audit.py`) against preregistration §2–§6 and the cited sources.
2. **Numbers against results.** A cross-document check compared every hand-written number and verdict in README,
   summary, paper, experiment reports, progress, plan, docs, site data and model card with `results/`.
3. **Citations against sources.** Two web passes checked every reference in the paper, the literature review and the
   state-of-the-art review: does the link resolve to the stated title, authors and year, and does the source support
   the sentence attached to it? Checked further: Claude Haiku 5.5's training cutoff and prices, Claude Code's CLI
   options, and the Hugging Face repositories (creation date, contents, file hashes).
4. **Raw agent evidence.** Read the agents' `build_weights.py` and their stream-json transcripts; checked what reaches
   the sandbox.
5. **New checks where a claim lacked a control.** These are labelled post hoc: H8 negative controls, a pooled and
   threshold-free memorisation analysis, transcript counts of self-test use, and an exact trend test.

## 2. Verified sound

- **Metrics match preregistration §4.**
  - KL(P_M ‖ P_M̂) is in nats and float64, the convention of [Conmy et al. 2023](https://arxiv.org/abs/2304.14997).
  - HS is a pooled 5-fold cross-validated ridge R², clipped to [0, 1], harmonic-meaned per site and averaged over
    three sites.
  - The invariance statements match [Kornblith et al. 2019, Table 1](https://arxiv.org/abs/1905.00414): regression R²
    is invariant to invertible maps of the predictor only.
- **Small-sample logic.** Minimum p is 1/20 for 3 vs 3 one-sided Mann–Whitney, 1/220 for 3 vs 9, and 1/64 for
  Wilcoxon with n = 6. A percentile bootstrap with three runs has C(5,3) = 10 distinct resamples, so the paper's warning
  is right. Verdicts follow §5–§6 and deviations 1–8.
- **Nanda et al. 2023, confirmed on the paper:**
  - architecture: p = 113, d = 128, 4 heads, 512 ReLU, no LayerNorm;
  - recipe: full-batch AdamW, lr 10⁻³, weight decay 1, 30 % split, 40,000 epochs (= steps, because training is full
    batch);
  - key frequencies {14, 35, 41, 42, 52};
  - the logit form;
  - restricted loss (§5.1), which matches grokviz `restricted_logits`.
- **The sandbox is target-blind.** The cwd is `/work`, and the prompt and templates are identical for every condition.
  No sandbox file mentions Nanda, grokking or the paper. The E0 and E1 explanations are byte-identical on every target.
- **The paper checkpoint mirrors are byte-identical.** `callummcdougall/…` and `arena-education/grokking_full_run_data`
  give the same LFS sha256, and it equals `VMI_PAPER_SHA256`.
- **Claude Haiku 5.5.**
  - Prices of $0.10 / $0.50 per MTok (≤ 100K tokens), as used by the cost proxy, match Anthropic's API reference.
  - The training-data cutoff of June 2026 matches the
    [models overview](https://platform.claude.com/docs/en/about-claude/models/overview).
- **The target repository is public, created 2026-10-21.** Its first upload already contained T0–T2.
- **Counts reproduce:** 96 Claude runs and 5 local runs; 9 retrains, 3 students and 5 random initialisations; 953 ledger
  requests. The verdict tables are identical across README, summary, paper, site and `hypotheses_round2.json`.
- **Citations resolve.** Every arXiv ID and link resolves to the stated work. Most attached claims are supported; the
  exceptions are listed in §3.

## 3. Findings and resolutions

Severity: **A** changes or qualifies a reported conclusion; **B** is a factual error or undisclosed methodology that
does not change a verdict; **C** is wording, presentation or reproducibility.

### A — changes or qualifies a conclusion

**A1. "T0–T2 have no published analysis" was false.**
- *Evidence:* [`BurnyCoder/grokking-modular-addition-runs/wd1_s1/analysis/key_freqs.json`](https://huggingface.co/BurnyCoder/grokking-modular-addition-runs/blob/main/wd1_s1/analysis/key_freqs.json)
  lists T0's key frequencies [2, 3, 23, 37, 39]. Every seed has full analyses, linked to a website. The repository
  was created 2026-10-21 (Hugging Face API `createdAt`).
- *Why it matters:* the contamination argument was stated on a false premise. It still holds on true ones: no paper
  analyses these runs, the analyses became public after the simulator's June 2026 cutoff, and the sandbox has no
  internet.
- *Resolution:* reworded in paper §3.1, §4.6 and §6, README, summary, literature review, learnings and round-1
  report. The paper now names each target's source (T-new and T-paper are not in that repository).

**A2. The memorisation result was reported on a subset of interchangeable runs.**
- *Evidence:* `results/explanations/*/E{0,1}/EXPLANATION.md` are byte-identical on every target. The sandbox carries no
  target identity (`scripts/run_one.sh`: cwd `/work`, the same prompt and templates).
- *Why it matters:* the three T0-E1 and the three T-paper-E1 runs are six draws from one condition. The abstract
  reported "E1: 3 of 3" from the T0 runs only. The T-paper runs were described only by their HS range.
- *What the agents' own build scripts show:* five of six E1 scripts hard-code at least four of the paper's five
  frequencies (e.g. T-paper s0 `KEYS = [14, 35, 41, 42, 52, 71]`, with 71 ≡ −42). One script picks frequencies by a
  random search.
- *A measurement gap:* the 0.25-threshold key-frequency rule reported T-paper s0 as using only {42, 52}. The new
  threshold-free spectrum share puts all of that replacement's W_L norm on the paper's frequencies.
- *Resolution:*
  - `analysis/frequencies.py` adds `declared_freqs`, `paper_norm_share` / `target_norm_share`, and grades every E0/E1
    replacement against both T0 and the published checkpoint.
  - `tables.memorisation` pools the runs, and the key results, §4.6 and the README are regenerated from it.
  - The conclusion is unchanged, and stronger: the pooled six E1 replacements score far higher against the published
    checkpoint than against T0.

**A3. H5 was misreported, and its scope was undisclosed.**
- *Evidence:* the abstract said "the agent beat the agent-free compiler on one target". The paper's own table listed
  four pairs beyond the CI, on three targets. Other places said "beats it on T2", "close to the compiler's builds"
  (followed by +0.179 in the same paragraph), "H5 and H6 cannot be tested" (summary), and called the compiler a
  "ceiling" (experiments.md, docs/architecture.md).
- *Scope:* `predictions.py` pooled T0 with the seed targets and silently dropped T-paper (`SEED_TARGETS[:-1]`). Yet
  §5's tests use the main simulator on T0, and on T0 the agent stays within the compiler's CI on all four
  explanations.
- *Resolution:* `predictions.h5_gaps` / `h5_summary` give one generated wording, used everywhere: T0 (preregistered);
  seed targets (extension); T-paper reported apart. "Ceiling" was replaced by "reference point, not a ceiling".

**A4. The agent repairs explanations and tunes against the self-test, and neither was disclosed.**
- *Evidence:* W-role cannot be built literally (the compiler's build has accuracy 0.0065), yet every agent build from
  it reaches accuracy 1.000.
- *Process:* agents announce sweeps in their narration ("I'll sweep the neuron bias", "I'll sweep the logit scale")
  and keep the value with the best self-test accuracy or least-squares fit. The static audit
  (`simulator/audit.py`) reads only the final `build_weights.py`.
- *Why it matters:* no target information is involved, because both criteria use the task labels only. But a score
  measures the explanation plus the agent's repair. The paper's "training loops and iterative optimisation are
  forbidden" read as if no tuning happened.
- *Resolution:* `analysis/agent_behaviour.py` counts self-test runs and announced sweeps from the transcripts
  (`results/agent_behaviour.json`, paper Appendix D). This is disclosed in §3.3, §5 and Limitations. The self-test
  ablation (E3 HS unchanged) is cited as evidence that, for true explanations, the self-test does not drive the score.

**A5. H8 had no specificity control.**
- *Evidence:* a Spearman ρ along one training run correlates any two quantities that both trend over training. The
  preregistered falsifier (ρ ≤ 0) is weak.
- *Resolution:* `nonagent.trajectory` now also grades the W-freq, E1 and E0 replacements against all 401 checkpoints
  (post hoc; no verdict uses them). Their ρ is reported beside H8 (§4.3, predictions table, trajectory figure in
  orange). The outcome strengthens H8: see §4 below.

**A6. Overclaims in the Discussion.**
- "HS separates it sharply from correct behaviour obtained any other way" is contradicted by W-alg: the Pizza
  algorithm gives correct behaviour and still scores HS 0.91. It now reads "obtained with other frequencies".
- "The explanation, not the agent, is the limiting factor" became "consistent with", because the compiler is not a
  ceiling.
- "Below some capability the method does not work" became "model size, 4-bit quantisation and harness are
  confounded" (paper §5; README highlight row).
- "A linear map over a whole site cannot see what is inside them" is now labelled an interpretation, not a tested
  fact.

**A7. The replication claim was too broad.**
- *Evidence:* "HS's rise with detail does not replicate". The seed targets ran no E1, so only the fine E2 → E4 part is
  tested there. On T0 the same E2–E4-only test passes.
- *Resolution:* a generated "T0 (E2–E4 only; post hoc, for comparison)" row in the replication table, and narrowed
  wording in the paper, README and summary.

### B — factual error or undisclosed methodology, no verdict change

**B1. "Claude Code has no step cap" is wrong.**
- *Evidence:* the Claude Code 2.1.330 binary contains the option `--max-turns <turns>`, also listed in the CLI
  reference. The runs used `--max-budget-usd` (`scripts/run_one.sh`) and no turn cap. `TASK.md` told every agent
  "about 60 minutes and 60 steps", a step limit only the local harness enforced.
- *Resolution:* fixed in paper §3.3, `agent_examples.py` and learnings; erratum in deviation 9 (amendment 2 is frozen).

**B2. Yip et al. 2024 give no "closed-form constructions".**
- *Evidence:* [arXiv:2412.03773](https://arxiv.org/abs/2412.03773) explains the MLPs of trained Pizza models as
  numerical integration, with error bounds.
- *Resolution:* reworded in paper §2. Gromov 2023 does give analytic weights.

**B3. Two works were cited but missing from the References,** and one reference lacked its venue.
- Missing: Chan et al. 2022 (causal scrubbing) and Kornblith et al. 2019.
- No venue: Geiger et al. (JMLR 26(83), 2025).
- *Resolution:* references added or completed.

**B4. The Heap et al. title is v2's (2026).** v1 (2025) was "Sparse Autoencoders Can Interpret Randomly Initialized
Transformers". Fuzzing is their main score, detection appears only in an appendix, and the authors say "in many
settings".
- *Resolution:* paper, literature review and SOTA review reworded; the reference is annotated.

**B5. Sutter et al.'s assumptions are not all "mild".** Their Theorem 1 needs countable inputs, injective and
surjective hidden layers, and a network that solves the task; §8 calls two of these strong.
- *Resolution:* the assumptions are named in paper §2.

**B6. Literature review overstatements.**
- Haklay et al. showed Claude Opus 4.1 listing the IOI circuit when prompted directly, not agents reproducing
  circuits during analysis.
- Poché et al. found explanations "added little over" no-explanation baselines, not that they "matched" them.
- Stander et al. argue for coset circuits, and Wu et al. 2024 find both accounts incomplete; "shown to be partly
  wrong" overstated this.
- FADE scores MLP neurons as well as SAE features.
- *Resolution:* all reworded.

**B7. State-of-the-art review details.**
- The Flash-Next GGUF size was wrong: the smallest are about 66 GB / 62 GiB (unsloth UD-IQ1_S), or 58.5 GB for a
  third-party quant, not "≈ 68 GiB".
- Claude Code's Linux sandbox uses a socat relay over Unix sockets to a host-side proxy (sandbox-runtime README); the
  docs page itself does not say "unix-socket bridge".
- The Terminal-Bench figures are attributed by llmrun.dev to Epoch AI, with the benchmark version not stated.
- The causal-scrubbing "% loss recovered" is defined in the appendix, §2.1.
- *Resolution:* all corrected.

**B8. The exact JT test was not exact for nine values.**
- *Evidence:* `stats.jonckheere` enumerated index permutations only up to eight values, so three levels × three runs
  (1,680 assignments) fell back to Monte-Carlo, despite its docstring.
- *Resolution:* the test now enumerates group assignments, with a brute-force test (`test_jonckheere_is_exact_…`).

**B9. The cost total was mislabelled.**
- *Evidence:* "103 runs (incl. checks)" and "$2.33 for all runs" include 6 stage-0 development runs and 1 plumbing
  check.
- *Resolution:* `tables.cost_split` and the cost table separate reported runs, development runs and checks.

**B10. "Why output KL fails" had no evidence attached,** although the secondary calibrated KL supports it directly.
- *Resolution:* a generated raw-versus-calibrated KL table (`kl-calibration-T0`) in paper §5.

**B11. No correction across hypotheses was stated.**
- *Resolution:* a generated Bonferroni sentence in Limitations, showing which supported tests would survive a
  correction over the eight hypotheses.

### C — wording, presentation, reproducibility

- **experiments.md:** the precise neuron function is in E1, not E3, and HS is ridge, not plain linear-regression R².
- **Round-2 report:**
  - the stale "ranking nearly unchanged" now covers the whitened variants;
  - deviation 8 had been omitted;
  - "below every true explanation" now reads E2–E4.
- **Round-1 report:** it referred to a CI its table does not have. **Summary:** it still said "same rules" for the
  replications.
- **README:**
  - "after the first five local runs" now notes the sixth, interrupted run;
  - the concrete-outputs table shows the seed-0 replicate, and now says so;
  - "every number below is regenerated" is narrowed to result numbers.
- **Versions:** they were typed by hand. `results/environment.json` now records them: Python, packages, the Claude
  Code version per run, bubblewrap, the WSL OS, the llama.cpp build and pandoc.
- **CUDA:** "CUDA 13.5" for llama.cpp could not be verified; the build ships CUDA 13 runtime DLLs, and the docs now say
  that.
- **Mirrors:** the paper-checkpoint mirrors are confirmed byte-identical (same LFS sha256).
- **"40,000 steps":** now said to equal the paper's 40,000 epochs (full batch).
- **Bills et al.:** their ablation score uses Jensen–Shannon divergence, not KL; this is now said where the paper
  writes "cf.".

## 4. Effect on the reported results

**No preregistered verdict changed.** H1 (HS supported, KL not), H2 (cannot tell at N = 3), H3, H4 and H7
(supported), H4b (not supported), H5/H6 (not evaluable) and H8 (supported) read as before. The values below are
from `results/` after `vmi analyse 2`, which gives no diff when run twice.

- **H8 reproduces, and its new control supports it.**
  - Recomputing the trajectory gives the same six E3/E4 Spearman ρ as before: min 0.751, median 0.774, over 401
    checkpoints, in 78.6 min on the GPU (`logs/trajectory_audit2_*.log`).
  - The post-hoc negative controls (`results/controls/trajectory_T0.json`, `negative_controls_by_level`):
    - E0: −0.83, −0.45, +0.14
    - W-freq: −0.40, −0.24, −0.38
    - E1: −0.58, −0.58, −0.57
  - Eight of nine are negative, and the largest is +0.14, far below every E3/E4 replacement. So the correlation is
    specific to replacements that carry T0's mechanism, not a generic time trend. H8 stays descriptive.
- **Memorisation, pooled (key results; §4.6), is stronger than the T0-only report suggested.**
  - Five of six E1 build scripts list at least four of the paper's five frequencies; the threshold rule detects at
    least four in three of six replacements.
  - On average 68 % of the E1 replacements' W_L spectrum lies on the paper's frequencies (chance 9 %; about 0 for
    T0's E2–E4 replacements).
  - The same weights score HS 0.08 against T0 and 0.70 against the published checkpoint. E0: one of three.
- **H5, reported in its scope.**
  - On T0, agent − compiler is −0.001 / +0.002 / −0.009 / −0.024 for E2 / E3 / E4 / W-freq: none beyond the
    bootstrap CI.
  - On the seed targets, the agent is above the compiler by sign in six of eleven pairs, and beyond the CI in four
    (T1 E2, T2 E3, T2 E4, T-new E4; largest +0.179, T2 E3).
  - On T-paper (not counted): E3 +0.073 beyond the CI.
  - Conclusion: the compiler is not a ceiling. H5's first half holds on its preregistered target and fails on the
    extension.
- **Replications.** The exact JT changes T1's p from 0.502 (Monte-Carlo) to 0.500. T2 stays at 0.500. The new T0
  E2–E4 row is supported (exact JT p 0.011, ρ 0.79), so the fine E2 → E4 rise holds on T0 and does not replicate on
  T1 and T2.
- **Calibrated KL.** Temperature calibration lowers mean KL by a median factor of about 8 to 1,400 per explanation,
  except for E4 (1.1×) and W-scramble (2.4×), whose runs include wrong answers. This supports "output KL mostly
  measures logit scale and wrong answers".
- **Agent process.**
  - 41 of 96 runs announce a sweep or tuning; the median is three self-test runs per run.
  - All six E1 runs announce tuning; no W-alg, W-role, W-scramble or E-paper run does (`results/agent_behaviour.json`).
  - The W-role compiler build has accuracy 0.007; every agent build has 1.000.
- **Multiplicity (post hoc Bonferroni over eight hypotheses).** H1's HS trend (p = 1.0·10⁻⁴) survives. H4
  (Holm-adjusted p = 0.009) and H7 (p = 0.016) would not.
- **Cost.** The 96 reported runs cost $2.20; development runs ($0.13) and plumbing checks bring the total to $2.33.

**Bottom line.** The paper's main conclusions survive this audit:
- output KL is not a valid score here;
- HS is valid at the frequency level, with two blind spots;
- an underspecified explanation is filled from memory on a published model.

What changed is precision:
- why the targets are uncontaminated;
- what H5 shows and where;
- that the score includes the agent's repair;
- how strong the memorisation evidence is;
- which supported tests would survive a multiplicity correction.

## 5. Not verified

- **Whether the target repository was public from its creation.** The Hugging Face API shows the creation and upload
  dates (2026-10-21), but not the visibility history. The contamination argument does not depend on it: every date
  is after the June 2026 cutoff.
- **That announced sweeps actually ran, and sweeps that were not announced.** The API does not return Claude's
  thinking, so `agent_behaviour.json` counts stated intent in the narration only.
- **Epoch AI's own Terminal-Bench page.** It returned 404; the figures are confirmed only on llmrun.dev, which
  attributes them to Epoch.
- **The CUDA minor version of the llama.cpp build** ("13.5"). Only the CUDA 13 runtime DLLs are visible, so the docs
  now say "CUDA 13 runtime".
- **Historical progress-log entries** (`reports/progress.md`, older sections). These are dated status notes, and their
  numbers were not re-derived one by one. Current claims live in the paper, README and summary, which were checked.
- **The round-1 report's generated blocks** were not regenerated (`vmi analyse 1` was not re-run, so that the round-1
  record stays as it was). Its frequency table keeps the pre-audit columns. `results/frequencies_round1.json` was
  recomputed with the new fields, and its old columns are unchanged.
