## 2. Findings (severity order) and what changed

**F1 — H1's verdict dropped a failed clause (evaluation error, now corrected).** §5 states H1 as "HS increases … from E1
to E4 on T0 (E0 … lies below E1)" and rules that "supported requires the stated direction and the stated statistical
criterion". The test covers E1–E4 only, and the verdict read "HS: supported", although E0's mean HS (0.130) is above
E1's (0.046). The clause has no preregistered test, so it now gets a direction-only verdict: H1 reads "HS trend E1→E4:
supported; E0 below E1: not observed (E0 above E1; direction only, no test preregistered); KL_out: not supported"
(`analysis/hypotheses.py`; text in the paper, README and summary).

**F2 — the T-paper replication of H1 left out levels it had (evaluation error, now corrected).** §5 re-tests H1 on the
seed targets "with the same tests". T-paper ran E1, E3 and E4, but the replication used E3 < E4 only ("cannot tell at
this N", JT p 0.650). Over every ladder level it ran (E1 < E3 < E4) the preregistered rule gives **not supported**
(exact JT p 0.061, ρ 0.63), with E1's memorised published frequencies raising its HS (`predictions.replication_rows`).

**F3 — the self-test ablation does not remove label feedback (interpretation error, claims withdrawn).** The ablation
removed `selftest.py` and the instruction to raise accuracy (`simulator/sandbox.py`), but the labels are the task itself
((a + b) mod 113, also returned by `forward.labels()`). All three runs without the self-test computed task accuracy
with their own code, and 27 of the 96 reported runs did so; every run checked accuracy one way or the other. The
earlier counter counted only `selftest.py` calls. The paper's "removing the self-test left E3's HS unchanged, so for
true explanations the self-test does not drive the score" is withdrawn; the claim is re-grounded on the agent-free
compiler (on T0 the agent stays within the compiler's level for E2–E4; on T2's E3 the agent's repair adds +0.179).
`analysis/agent_behaviour.py` now counts own label checks (column in Appendix D; `results/agent_behaviour.json`).

**F4 — the alignment class at `mlp_post` is wider than the MLP's symmetry group (method rationale, erratum).** The
preregistered rationale ("the residual stream is defined only up to an invertible linear map, so the alignment class
is linear … and no wider") holds for the two residual sites. At `mlp_post` the symmetry is permutation and positive
per-neuron scaling, and a linear regression can recombine neurons freely, so it is wider than the group. This is a
plausible cause of the scrambled-neuron blind spot (W-scramble passes HS, while the group-matched matched-neuron
correlation separates it). The frozen `TASK.md` told agents the comparison allows "any reordering/positive rescaling of
neurons", which understates what the metric allows. Primary metric unchanged; rationale corrected in the paper §3.4,
Appendix B reading, `docs/architecture.md`, `reports/state-of-the-art-review.md`, `grader/metrics.py`.

**F5 — the true explanations' replacements are Pizza-like (new post-hoc finding).** The W-alg control assumes T0 is a
Clock. With Zhong et al.'s distance irrelevance q (Def. 4.2; §4.1.2: 0–0.4 typical of Pizza, 0.4–1 of Clock), every
target is Clock-like (0.59–0.81; T0 0.75) and the literal Pizza build is Pizza-like (0.003): **the W-alg control is
valid as designed**. But the compiler's literal E1–E4 builds (0.18–0.30) and the agents' E1–E3 replacements
(0.13–0.18; E4 0.41) are Pizza-like too, and HS still rates the E2–E4 replacements 0.89–0.94. The rendered E1–E3
explanations prescribe the same MLP neuron function as the Pizza text (amendment 2 item 3) and do not convey what
makes T0 a Clock. Consequences: H2's E3 > W-alg compares two Pizza-like builds; the Clock/Pizza blind spot of HS is
shown more directly by the high HS of Pizza-like E3 replacements against a Clock target; "true" explanations are true
at the level of frequencies and component roles. The paper's "the non-linearity that distinguishes Clock from Pizza"
was inaccurate (the texts differ in attention and in the predicted logit factor, not in the neuron function) and is
corrected. Gradient symmetricity (Def. 4.1) is strongly negative for every hand-built replacement because their
near-constant attention is computed from the embeddings and the full gradient points off the data manifold (literal
Pizza: −0.87; +1.00 with the attention pattern held fixed); it is reported with a labelled fixed-attention variant and
not used for the reading. Table: paper §5 (`clock-pizza-T0`), `results/controls/clock_pizza.json`, `vmi clockpizza`.

**F6 — H1's trend test was Monte-Carlo, not exact.** `stats.jonckheere` was exact only up to 50,000 assignments, so
H1's 4 × 3 design (369,600) used 20,000 shuffles (one hit, p 1.0e-04). A vectorised enumeration makes it exact
(p 9.47e-05); no verdict changes. Test added (`tests/test_report.py`).

## 3. Wording and citation corrections

- T1: tied with `wd1_s9` for the fewest key frequencies (3); the rule took the lower seed (paper §3.1, plan).
- Target repository: created and first uploaded 2026-10-21 (Hugging Face API); when it became public is not recorded,
  so "public since" became "uploaded on" (paper, README, summary, literature review, learnings).
- Sutter et al. 2025: assumptions now listed as in Theorem 1 (countable inputs, input-injectivity, strict
  output-surjectivity, matchable partial orderings, a network that solves the task; the authors call injectivity and
  surjectivity strong), conclusion "input-restricted distributed abstraction", class "decided case by case" (paper,
  README, literature review).
- Poché et al. 2026: the paper does not use the term "output simulatability"; it studies LLM simulators predicting a
  text classifier's outputs from concept explanations, where explanations add little over matched no-explanation
  baselines because the simulator can solve the task from meaningful class names (paper, README, both reviews).
- Paulo et al. 2024: "classification-based scorers" → "cheaper scorers such as detection and fuzzing" (only those two
  are classification tasks).
- Huang et al. 2023: the abstract's wording — the most confident explanations (Bills et al.'s GPT-2 XL explanations
  with score ≥ 0.8) have high error rates and little to no causal efficacy.
- Yip et al. 2024: constant-attention (Pizza) models at p = 59; their logits are closer to the Clock form.
- Haklay et al. 2026: Claude Opus 4.1 listed the IOI circuit's components from memory when prompted.
- Zhong et al. 2023: "full attention gives Clock" → typically, not always (a width-1024 full-attention model learned
  Pizza, App. H); output KL does separate the literal Clock and Pizza builds (no longer "untested"). "Same accuracy" was
  checked and is correct for trained Pizza models.
- Cammarata et al.: Sharkey et al. describe *Curve Detectors* as validated by handcrafted replacements; the hand-built
  network is in *Curve Circuits* (2021), built from scratch and compared with InceptionV1, not substituted into it.
- State-of-the-art review: OpenCode's `--format json`, `--thinking`, `--auto` are documented in the v2.3.2 source, not
  the docs site; Qwen3.8-Flash-Next's smaller GGUFs are expert-pruned third-party builds; grokviz's 5.5474e-8 agrees
  with Nanda et al.'s 5.54e-8 to 0.2 %; CKA's top-PC dominance now cited to Ding et al. §5; the 33 tok/s estimate is
  for a different GPU; Ollama's missing `--n-cpu-moe` equivalent linked to its issue tracker.
- Learnings: Clock vs Pizza is "same accuracy, different logit patterns", not "same behaviour".
- README: "Holds on a network trained after the freeze" now shows E3 (0.910, the preregistered H2 level) next to E4;
  "Strength" names the test behind each supported hypothesis (H3 is a comparison of means, H8 descriptive); "right
  answers, wrong mechanism" renamed "right answers from the wrong key frequencies" (W-freq is the same Clock algorithm
  on other frequencies); the reference compiler builds "what the explanation's parameters determine, with fixed
  defaults where it is silent"; planned-runs and the README diagram say "no network except the model endpoint".

## 5. Effect on conclusions

No primary metric and no preregistered test result changed. H1's reported verdict now shows its failed E0 clause; the
T-paper replication of H1 reads "not supported" instead of "cannot tell". The self-test ablation no longer supports any
claim about label feedback. The negative result on Clock versus Pizza stands and is sharper: HS rates Pizza-like
replacements of a Clock target about 0.9, and the true explanations as rendered are incomplete about what makes T0 a
Clock. Remaining limitations are unchanged: N = 3, one task family, one simulator.
