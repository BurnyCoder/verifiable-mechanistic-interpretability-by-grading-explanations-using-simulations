# Preregistration v1 — Is weights-blind simulation a valid score for mechanistic explanations?

*Libor "Burny" Burian, Victor Levoso. Version 1, 2026-11-21. Written and pushed before any agent run, grading run
or analysis of this project. Changes after this point are recorded as dated amendments at the end of this file;
nothing above the amendments section is edited.*

## 1. Question

Given an explanation (text, math, tables) of how a trained network works, a **simulator** — a local LLM agent that is
never shown the network's weights and has no internet access — writes the weights of a **replacement** network of the
same architecture. The explanation's **simulation score** compares the replacement with the original:

- **output fidelity** `KL_out` (lower is better), and
- **hidden-state similarity** `HS` (higher is better).

**Primary question:** does this score measure explanation quality? Concretely: does it increase with true detail,
decrease for false explanations of equal length, separate a correct-behaviour/wrong-mechanism explanation that output
fidelity alone cannot separate, and depend on the explanation rather than on the simulator?

## 2. Setting (fixed)

- **Architecture** (all targets): the one-layer modular-addition transformer of Nanda et al. 2023
  ([arXiv:2301.05217](https://arxiv.org/abs/2301.05217)), p = 113, d_model 128, 4 heads × 32, d_mlp 512, ReLU,
  no LayerNorm, parameter layout of the paper's code (via `grokviz.model.GrokTransformer`, commit `d52a898`).
- **Targets** (`BurnyCoder/grokking-modular-addition-runs`, revision `98c61de`, final checkpoint, step 40,000):
  T0 = `wd1_s1` (main), T1 = `wd1_s4`, T2 = `wd1_s8`, dev = `wd1_s10` (development only, never reported),
  T-paper = the paper's checkpoint at epoch 40,000 (`callummcdougall/grokking_full_run_data` revision `80e5dbb`),
  T-new = a model trained by this project after the protocol freeze (init = split seed 11; next seed if it does not
  reach 100 % test accuracy). A target must have 100 % test accuracy; otherwise the next `wd1` seed in the same role's
  rule is used (T0: first seed whose key frequencies differ from the paper's {14, 35, 41, 42, 52}; T1: fewest key
  frequencies; T2: most).
- **Simulator** (main): OpenCode 2.3.2 + Qwen3.6-35B-A3B (GGUF UD-IQ4_XS, revision `a483e9e`) on llama.cpp b12600,
  sampling temperature 0.6, in a bubblewrap sandbox with no network and no path to any target file. The agent may use
  numpy and closed-form linear algebra (e.g. `np.linalg.lstsq`); it may **not** use gradient descent, optimisers or any
  loop that updates weights to reduce a loss (static audit of `build_weights.py` + manual review of flagged scripts;
  flagged runs are reported and excluded from the primary analysis). The sandbox provides `selftest.py`, which reports
  shapes and accuracy against the task labels (a+b) mod 113 — never anything computed from a target.

## 3. Explanations (generated by script from each target; no hand-typed numbers)

| ID | Content | Truth |
|---|---|---|
| E0 | task + architecture only | true, no mechanism |
| E1 | algorithm sketch (Fourier multiplication via trig identities), no model-specific numbers | true |
| E2 | E1 + the target's key frequencies + the role of embedding, attention, MLP, unembedding | true |
| E3 | E2 + per-frequency logit amplitudes, neurons per frequency, attention-pattern fits per head, logit scale | true |
| E4 | E3 + per-neuron table (frequency, input phases/gains, bias, output phase/gain) as CSV, per-head summary | true |
| W-freq | E3 with every key frequency replaced by another frequency (fixed seeded draw, disjoint from the true set) | false mechanism, correct behaviour |
| W-alg | E3-length description of the Pizza algorithm (Zhong et al. 2023) at the target's frequencies | false for a Clock model |
| W-role | E3 with components misattributed: the MLP and unembedding are described as using a disjoint frequency set from the embedding and attention | false |
| W-scramble | E4 with each neuron's frequency redrawn uniformly from the key set and its phases redrawn uniformly | false at neuron level |
| E-paper | T-paper only: the published explanation, paraphrased, with the paper's own Table 1–2 numbers | as published |

Each explanation's length is recorded as characters, gzip bytes and count of numbers.

## 4. Metrics (primary metrics fixed here)

Inputs: all 113² pairs `(a, b, =)`; read-out at the "=" position; logits restricted to the 113 number classes.

**Primary 1 — output fidelity.** `KL_out = mean over the 12,769 inputs of KL(P_M ‖ P_M̂)`, P = softmax over the 113
logits, natural log, float64.

**Primary 2 — hidden-state similarity.** At three sites at the "=" position — `resid_mid` (after attention, 128-d),
`mlp_post` (512-d), `resid_post` (128-d) — compute 5-fold cross-validated ridge-regression variance explained in both
directions, R²(M̂→M) ("completeness") and R²(M→M̂) ("soundness"):
R²(X→Y) = 1 − Σ‖Y − Ŷ‖² / Σ‖Y − Ȳ‖², pooled over output dimensions, held-out folds only, ridge λ = 1e-6 × trace(XᵀX)/d,
folds fixed by seed 0, clipped to [0, 1]. Site score = harmonic mean of the two directions; **HS = mean of the three site
scores**. Rationale: without LayerNorm the residual stream is defined only up to an invertible linear map, so the
alignment class is linear (invariant to exactly that group) and no wider (Sutter et al. 2025,
[arXiv:2507.08802](https://arxiv.org/abs/2507.08802)).

**Secondary metrics** (reported, not used for primary verdicts): argmax agreement with M; task accuracy; centred-logit
fraction of variance unexplained; KL after temperature calibration of M̂; Hungarian-matched neuron correlation; head-matched
attention-pattern distance; linear CKA; orthogonal Procrustes distance; embedding Fourier-spectrum overlap; stitching KL
(least-squares linear map from M̂'s `resid_mid` into M's, then M's MLP and unembedding; KL on held-out inputs).

**Failed runs** (no valid `weights.npz`, wrong shapes, non-finite values, or audit violation) are scored as the all-zero
model (uniform output, HS = 0) and counted in a failure rate. Primary analyses include failures; analyses without them
are reported alongside.

## 5. Hypotheses, tests and falsification criteria

All tests use per-run scores of the main simulator unless stated. "Supported" requires the stated direction **and**
the stated statistical criterion; otherwise "not supported", or "cannot tell at this N" when the test is undefined at
the current N (see §6).

| ID | Hypothesis | Test | Falsified if |
|---|---|---|---|
| **H1 validity** | Scores improve with true detail: HS increases and KL_out decreases from E1 to E4 on T0 (E0, run in the controls stage, lies below E1). | Jonckheere–Terpstra trend test over levels E1 < E2 < E3 < E4, one-sided, α = 0.05; Spearman ρ with bootstrap 95 % CI (10,000 resamples of runs within level). | trend p ≥ 0.05 or ρ CI includes 0 (for HS; KL_out tested separately, same rule). |
| **H2 discrimination** | True explanations beat length-matched false ones on HS: E3 > W-freq, E3 > W-alg, E3 > W-role, E4 > W-scramble (T0). | Four one-sided Mann–Whitney U tests, Holm-corrected, α = 0.05; effect size = rank-biserial r and difference of means with bootstrap CI. | any comparison not significant after Holm, or its direction reversed. Reported per comparison. |
| **H3 behaviour ≠ mechanism** | W-freq replacements match M's behaviour while their hidden states do not: mean argmax agreement ≥ 0.99, mean KL_out within the range [min, max] of the condition means of E2, E3, E4, and mean HS below the condition mean of each of E2, E3, E4. | Direct comparison of condition means; HS difference to each of E2–E4 with bootstrap CI. | mean KL_out of W-freq exceeds the maximum condition mean of E2–E4 (output KL alone already separates it), or HS does not fall below all three. |
| **H4 added value** | E3 and E4 replacements beat independent retrains (the 9 other `wd1` seeds graded against T0) on HS. Secondary, two-sided, no predicted direction: E3/E4 vs logit-distilled students. | One-sided Mann–Whitney per level vs the 9 retrain scores, Holm over {E3, E4}; two-sided for students. | not significant after Holm. |
| **H4b grader calibration** | On the planted-mechanism series (reference-compiled E3 model for T0 trained further, snapshots at 0, 100, 1,000, 10,000 steps), the step-0 model graded against each snapshot gives HS = 1 and KL_out = 0 at step 0 and HS strictly decreasing / KL_out strictly increasing over the snapshots. | Deterministic; checked exactly. | any non-monotonicity. This would mean the grader is unreliable. |
| **H5 simulator gap** | Agent scores do not exceed the reference compiler's on the same explanation, and the gap shrinks with simulator capability (Qwen3.5-4B → Qwen3.5-9B → Qwen3.6-35B-A3B) on {E2, E3, E4, W-freq}. | Per explanation: mean agent HS ≤ compiler HS. Gap trend: Jonckheere–Terpstra over the three models on the per-run gaps, one-sided. | agent mean exceeds the compiler on any explanation by more than its bootstrap CI, or no trend. |
| **H6 simulator invariance** (secondary) | The three local models rank {E2, E3, E4, W-freq} the same way on mean HS. | Kendall's W across the three rankings, permutation p-value. | W not significant at α = 0.05. With only 4 items this is a weak test. |
| **H7 specificity** | A replacement built from T0's explanation scores higher HS against T0 than against any other target (T1, T2, dev, T-paper) or no-mechanism model (`wd0_s*`, `rand_s*`). | Per E3/E4 run: d = HS(T0) − max over wrong targets; one-sided Wilcoxon signed-rank on d. | median d ≤ 0 or p ≥ 0.05. |
| **H8 trajectory** (secondary) | Against T0's 401 checkpoints, E3/E4 replacements' HS rises through circuit formation and cleanup, tracking the fall of restricted loss. | Spearman ρ between HS(t) and −log restricted loss(t). | ρ ≤ 0 (descriptive). |

Stage assignment: H1 on the main-method stage; H2, H3, H4b, H7, H8 on the controls stage; H4 on the baselines stage;
H5, H6 on the ablations stage. Seed-sensitivity results (T1, T2, T-new, T-paper) re-test H1–H3 on those targets as
replications, reported per target with the same tests.

## 6. Rounds, sample sizes and stopping

Every agent condition is run in three rounds: **N = 1** (run seed 0), then **N = 3** (seeds 1–2 added), then
**N = 10** (seeds 3–9 added). Each round runs the stages in this order: main method, controls, baselines, ablations,
hyperparameter sensitivity, seed sensitivity. **Every hypothesis is evaluated after every round** with the analysis
above, and every verdict, table and figure is labelled with its N ("at N = 1 — not yet N = 3 or N = 10"; "at N = 3 —
not yet N = 10"; "at N = 10"). What each N supports: at N = 1, rank tests between two single runs are undefined →
verdicts for H2, H4 and H7 are "cannot tell at this N", while H1 (4 levels: exact one-sided permutation p = 1/24 for a
perfect monotone order), H3 (comparison of means) and the deterministic H4b can be evaluated; at N = 3, intervals exist
but are wide and a 3-vs-3 one-sided Mann–Whitney cannot go below p = 0.05 (minimum 1/20); N = 10 is the full analysis.
Nothing in the protocol, prompts or analysis changes between rounds. The study stops on time, never on results; if
round 3 cannot finish within the week, it stops at a stage boundary and the last completed verdicts stand with their N.

## 7. Controls and baselines (no agent unless stated)

Random-init models (5 seeds) · wrong targets (H7) · planted-mechanism calibration (H4b) · training trajectory (H8) ·
independent retrains (9 `wd1` seeds; for T-paper also `wd1_s0`, whose key frequencies equal the paper's, and the three
`split0_init*` runs) · logit-distilled students (3 per main target, trained on all 113² inputs to match M's logits) ·
**reference compiler** (deterministic script that builds weights from each explanation's parameter file; the agent-free
ceiling) · Fourier-restricted M and the weights dump (ceilings and the far end of the length axis).

## 8. Ablations and sensitivity analyses

Ablations: simulator size (Qwen3.5-9B, Qwen3.5-4B, same server and prompt) × {E2, E3, E4, W-freq}; explanation format
at fixed E3 content (math-heavy and code-style versions vs prose); self-test tool removed (E3). Hyperparameter
sensitivity: temperature 0.2 and 1.0 × {E3, W-freq}; grader settings without new runs (ridge λ × 10^±2, 3 and 10 folds,
each site alone, orthogonal instead of general linear alignment, failed runs excluded); explainer thresholds (key-frequency
τ ∈ {0.15, 0.35}, neuron FVE threshold ∈ {0.75, 0.9}) with re-compiled explanations. Seed sensitivity: targets T1, T2
× {E2, E3, E4, W-freq}; T-new × {E3, E4, W-freq}; T-paper × {E-paper, E1, E3, E4, W-freq}; redrawn W-freq and W-scramble
(3 seeds); grader fold seeds.

## 9. Development, freeze and contamination controls

All prompts, templates and the sandbox are developed on the dev target only. Before round 1, a dated amendment freezes
the agent prompt, `TASK.md`, explanation templates, simulator settings and analysis code (git commit hash). T-new is
trained only after that freeze. Targets T0–T2 and T-new have never appeared in a paper; T-paper's frequencies are
public, so its results are flagged as contamination-prone. The E0 and E1 conditions measure what the simulator achieves
from priors alone.

## 10. Reporting

All results — including failed runs, negative results and audit-flagged runs — are reported. Every number in the paper,
README and site is generated by a script from `results/`. Analyses not listed here are labelled post-hoc.

## Amendments

### Amendment 1 — 2026-11-21, stage 0 (before any reported agent run; only the dev target had been analysed)

1. **Local LLM context 65,536 → 49,152 tokens; `--n-cpu-moe 34`; port 8091.** At 64k context the non-expert weights
   plus KV cache used 5.1 GB of the 8 GB VRAM, leaving no room for expert weights on the GPU. Throughput was measured
   cold (first request after loading, while the OS pages the memory-mapped 17.7 GB file in) and warm. Warm, at 48k
   context with 34 of the MoE layers' experts in system RAM: 289 prompt tokens/s and 21.6 generated tokens/s
   (`results/stage0/llm_tuning.json`), above the preregistered 8 tokens/s threshold, so **Qwen3.6-35B-A3B remains the
   main simulator** and the fallback is not triggered. Port 8080 could not be bound on this machine.
2. **Grading precision: float64** (§4 did not state it). Both models are evaluated in float64, matching the agent's
   numpy self-test; float32 targets are cast exactly.
3. **Matched-neuron correlation** (secondary) is averaged over the target's live neurons (neurons with non-zero variance
   over the 113² inputs); dead target neurons carry no mechanism.
4. **Reference compiler details** (a baseline, so not part of the agent protocol): ridge least squares
   (λ = 1e-8·tr(XᵀX)/d) for neuron inputs and the read-out; the unembedding may read the residual stream directly as
   well as the MLP output. Full algorithm in `src/vmi/reference/compile.py`.
5. **Reproduction check** (stage 0) did not reproduce the published weights bitwise: grokviz's trainer is deterministic
   only for the same set of co-trained runs. Key frequencies were reproduced for `wd1_s10` but not exactly for `wd1_s1`
   (`results/training/reproduction_check.json`). Targets remain the published checkpoints; T-new is trained alone.
6. **E-paper spec:** the paper states only the k = 14 cluster size (44 of 433 clustered neurons); the compiler splits
   the remaining 389 equally over the other four frequencies.

### Amendment 2 — 2026-11-21, stage 0 agent development and protocol freeze (dev target only; no reported run yet)

Eleven agent smoke runs on the dev target `wd1_s10` (details and transcripts: `reports/experiments/learnings.md`,
`results/runs/dev__*.json`). Changes, each made after a dev-target failure and applied identically to every condition:

1. **Local LLM settings.** Context 49,152 → 81,920 tokens; thinking budget 16,384 tokens per model turn (server flag)
   and 24,576 output tokens per turn; sampling = the Qwen3.6 model card's preset for thinking-mode precise coding
   (temperature 0.6, top-p 0.95, top-k 20, min-p 0, presence penalty 0). Run cap 40 → 60 minutes (one full turn takes
   ~20 minutes at ~21 generated tokens/s); 60 steps unchanged.
2. **Sandbox files.** A starter `build_weights.py` that saves all-zero arrays of the right shapes; `TASK.md` gains a
   short section on the time/step budget. Runs that leave the starter unchanged are flagged and score as the zero model.
3. **Explanation text (design fix).** The Clock algorithm's MLP step now states the neuron function as precisely as the
   Pizza text (W-alg) already did: pre-activation ≈ bias + A·[cos(w_k a + φ) + cos(w_k b + φ)], whose ReLU contains
   the products. Before, the true explanation was vaguer than the false one, which would have biased H2. Checked on the
   dev target (a/b amplitude ratio median 0.999, phase difference median 0.1°). E-paper keeps the paper's wording.
4. **Harness.** OpenCode is replaced by a minimal bash-only harness following mini-SWE-agent's design
   (`src/vmi/simulator/harness.py`): one command per reply, linear history with observations as user messages, a
   truncated reply kept with a note, old messages elided before the context overflows; same sandbox, limits and
   logging. OpenCode's truncation handling, early compaction and session-ending errors caused most stage-0 failures.
   The switch coincided with change 3 (confound stated).
5. **Stage-0 decision rule** (fixed before any Claude run): a simulator "works" if one dev-target run reaches task
   accuracy ≥ 5 % (chance 0.885 %).
6. **Main simulator: Claude Haiku 5.5 in Claude Code (user decision, 2026-11-21).** No local Qwen model met rule 5 on
   the dev target (Qwen3.6-35B-A3B: best 2.44 % on E4 over eight runs; Qwen3.5-9B: 0.88 %; Qwen3.5-4B: no valid
   weights). Following the user's escalation rule (newest Haiku, then Sonnet, then Opus, each only if the previous
   stays at chance; API credits; $20 total cap), Claude Haiku 5.5 was tried first and met the rule in its first run
   (dev × E4: accuracy 100 %, output KL 3.6·10⁻⁷ nats, HS 0.985, $0.02), so Sonnet and Opus were not run.
   **This replaces §2's local-only main simulator.** Setup: Claude Code 2.1.330 (`--bare`, stream-json, permissions
   bypassed inside the sandbox, WebFetch/WebSearch disallowed, no session persistence), model `claude-haiku-5-5` with
   its default sampling (Claude 5.5 models reject non-default sampling parameters) and default effort `medium`, the
   same offline bubblewrap sandbox and 60-minute cap; a proxy outside the sandbox injects the API key and workspace id,
   allows only the Messages endpoint and the run's models, rejects server-side tools with internet access, and enforces
   a $2 per-run and $20 total cap from a request ledger (`results/claude/ledger.jsonl`). Claude Code has no step cap,
   so time and budget are the limits.
7. **Run matrix consequences.** The local Qwen models (custom harness) become the simulator-capability ablation:
   {Qwen3.6-35B-A3B, Qwen3.5-9B, Qwen3.5-4B} × {E2, E3, E4, W-freq} (12 conditions; previously 9B and 4B only).
   The temperature sweep is impossible on Claude 5.5 and is replaced by **effort low and high** (default medium) ×
   {E3, W-freq}. Format and self-test ablations, controls, main method and seed sensitivity use Haiku. Total: 44
   conditions per round (was 40); rounds and seeds unchanged (N = 1, 3, 10). At ~$0.02 per Haiku run on the dev
   target, all Haiku runs of the three rounds (32 + 64 + 224) project to ≈ $7; the $20 cap stops the study if
   exceeded, and the write-up then states the N reached.
8. **What the dev target showed** (protocol development only, N = 1, never reported as results): Haiku × {E0, E1, E2,
   E3, E4, W-freq} reached accuracy 100 / 100 / 99.75 / 100 / 100 / 98.3 % and HS 0.166 / 0.069 / 0.944 / 0.953 /
   0.985 / 0.096 (`results/runs/dev__*.json`). One flagged build script (E0) was reviewed manually as valid

9. **Contamination note.** Claude models may know Nanda et al. (2023) and the paper's frequencies; T-paper stays
